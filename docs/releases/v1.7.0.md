# BridgeTap 1.7.0 - OneClient HUD styles, server presets and replay video export

Minecraft **1.8.9** - **Forge** and **OneClient / Ornithe Fabric** editions. Install exactly one edition. The Fabric JAR uses Ornithe mappings; it is not compatible with arbitrary Legacy Fabric/Yarn profiles.

## Added

- Optional OneClient/OneConfig integration, credited **by sggn**, with native settings and three independent HUD-editor overlays: bridge coordinates, replay information and replay keystrokes.
- Native RGB color pickers, text/background/shadow styling, and independent pressed/released keystroke colors. The original replay, island and preset menus remain available.
- **Velo Z decimals (jump -1t)**: display the fractional absolute Z coordinate one tick before each jump beside its flat/speed entry. Each entry keeps its own sample. Enable the option in HUD settings; choose **Velo** in Overlay colors or the coordinate HUD's OneClient Settings tab. Jump-coordinate offsets do not change this sample.
- Per-server island preset bindings, portable `.btpreset` sharing, and undo/redo for grouped island-editor changes.
- Replay MP4 export at 30/60/120 FPS with recorded keystrokes/CPS, POV/follow/overview cameras, a construction-block hotbar, and a frozen ending showing the saved run time. Replay-video exports are silent because replay recordings do not contain game audio.
- Evidence-based fail analysis that reports recorded observations without guessing missing data.
- McPlay-only mode detection and mode filters/subfolders: **16 blocks = Extra Short**, **28 = Short**, **51 = Normal**, **83 = Long**. Height is ignored; other servers retain Unknown unless supported separately. Parent server folders include all their mode subfolders. Personal folder assignments are preserved.
- Gradle Wrapper and a portable build producing both editions in `build/libs`.

## Fixed

- Preset anchoring against the original start island and clear, unblurred world placement views.
- Replay placement/input alignment: new v5 recordings retain the original starting pose and use a consistent tick-boundary timeline. Tagged v4 recordings receive the compatible playback correction without rewriting their original timestamps.
- Replay sticks have no navigation cooldown: **one tick while paused**, **one second while playing**. Pause/speed/exit retain their own input handling.
- Native clip readback fallbacks and replay-video frame scheduling/backpressure.

## Downloads and upgrade

- **Forge:** `BridgeTap-1.7.0-Forge-1.8.9.jar` (Java 8+, tested with Forge 11.15.1.2318).
- **OneClient / Ornithe Fabric:** `BridgeTap-1.7.0-OneClient.jar`. Standalone Ornithe works without OneConfig; native OneClient integration requires OneConfig 1.7.0 and Java 21+ with its normal dependencies.
- Replace the previous BridgeTap JAR, keep only one edition, and restart Minecraft. Existing replay/island/preset data remains readable. Older summaries cannot reconstruct missing pre-jump samples.
- **Native clips/audio and Windows replay-video encoding now use a separate optional tools pack:** [BridgeTap-clip-tools-windows-x64.zip](https://github.com/sgggnnn/bridgetap/releases/download/v1.7.0/BridgeTap-clip-tools-windows-x64.zip). Extract it into your Minecraft game directory (the directory containing `mods`), producing `config/bridgetap/tools/ffmpeg.exe` and `config/bridgetap/tools/bridgetap-loopback.exe`. Restart the buffer afterward. Previously extracted tools with the correct pinned hashes are also supported.
- The mod JARs contain no executable binaries and never download or extract tools at runtime. Installed tools are checksum-verified. This is not a guarantee against antivirus detections; do not disable protection or add exclusions as a workaround.
- The rolling clip buffer starts OFF each launch. F9 saves the recent buffer. Windows audio records the default output, including other apps on that device, and never records the microphone.
- Actual live 120 FPS capture requires sufficient game FPS, GPU support and encoder throughput. Replay-video export instead advances the recorded scene with a fixed frame schedule.

## Validation and limits

- Core regressions, exact pre-jump sampling and independent Velo color/persistence checks.
- OneClient API contracts with native HUD color controls; bitmap-font menu previews.
- Forge native hooks and LaunchWrapper/Mixin smoke checks.
- Thirty-second 60/120 FPS native clips, decoded frame counts and orientation checks; explicit tools installation and checksum rejection tests.
- No claim of graphical in-game verification on every client/GPU.
- Customized OneLauncher integration sources are included under `integrations/oneclient`. No customized launcher executable is shipped; its full build/type check still requires Windows build tools.
